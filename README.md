# Personal Finance Companion

MIS2001 小组项目：结合个人财务档案、历史决策与市场数据的个人金融规划助手。采用 Flask、HTML/CSS/JavaScript 与本地 SQLite 的模块化单体结构，支持非流式模型聊天和独立连通检查。

## 设计与当前能力

- **SP（Structured Profile）**：保存当前已确认的结构化财务档案，表示当前有效状态。
- **CA（Conversation Archive）**：保存原始聊天、会话摘要与历史重要决策概览 CA Overview，解释历史变化。
- **MD（Market Data）**：保存规范化、有明确来源和时间的市场数据。

每轮聊天默认提供精简 SP、CA Overview 和近期消息；模型可按需调用历史摘要、行情和储蓄目标计算工具。当前方案不使用 RAG、Embedding 或向量数据库。

**T01–T04 已实现**：四个中文业务页签与 `/api` JSON 接口，可查看/编辑财务档案、目标和持仓，创建会话并保存用户消息，读取原文/摘要/CA Overview，确认或拒绝已有财务候选，查看和手动刷新模拟行情。沿用已有 Python 服务、SQLite 显式初始化/备份/版本迁移和 CLI。

**T06 已接入**：保留 AKShare 方案，支持贵州茅台不复权日线收盘价、上证指数日线收盘点位、基金 001186 正式单位净值。默认仍为固定虚构行情；真实模式须显式选择，刷新需要外网，无需密钥。两种模式均非实时行情。

**T05 已实现**：网页会话发送、模型回答及 SQLite 持久化，失败重试与重复请求保护；通过 OpenAI 官方 Python SDK 连接百炼兼容接口，复用外部配置与独立连通检查。

**T07 已实现**：用户明确点击归档后生成结构化摘要，更新跨会话 Overview，由模型理解意图并提取基础金额/风险偏好待确认候选。后端校验输出契约和用户原文引用，不重新解析自然语言。归档不会修改当前 SP，候选仍需用户核对后确认或拒绝。

**T08 已实现**：现有聊天接口串联三个受限工具：关键词查本地摘要、按当前提供器目录查行情、用 Decimal 计算固定月存入目标。工具参数由后端校验，模型解释结果；只保存用户问题和最终回复，不保存中间工具消息。无需新增依赖或数据库迁移，结构仍为 v4。

**尚未实现**：流式回复、后台调度、登录/多用户、交易、收益预测和完整 Dashboard。普通聊天不会自动归档或修改 SP；目标和持仓暂不自动提取。`create_app()`、首页 HTML 和 `/health` 不读取密钥、不调用模型或业务数据库；GET 仅查询，不触发模型。

## 安装与运行

本轮在 Windows、Python **3.11.5**、SQLite **3.42.0**、Flask **3.1.1**、AKShare **1.20.18** 上验证。建议先使用 Python 3.11；其他 Python 版本尚未验证。`sqlite3` 随 Python 提供。

在 VS Code 打开项目文件夹，选择自己已有的 Python 解释器，在项目根目录新建终端。环境名称不限，不强制创建 Conda 或虚拟环境；用下面命令确认终端实际使用的解释器：

```powershell
python -c "import sys, sqlite3; print(sys.executable); print(sys.version); print(sqlite3.sqlite_version)"
python -c "from importlib.metadata import version; print(version('Flask'))"
python -m pip show akshare
```

若缺少依赖或需要对齐版本，再执行安装；已有兼容版本时不要批量升级环境：

```powershell
python -m pip install -r requirements.txt -c constraints.txt
```

直接运行依赖为 `Flask==3.1.1`、`akshare==1.20.18`、`openai==2.8.1`。沿用兼容的官方 SDK 2.8.1，复用已有 httpx/anyio；未为了追新升级现有依赖。AKShare 与模型 SDK 均延迟导入，纯页面/mock 行情不需模型密钥；完整离线测试需 SDK 及其依赖，但模型网络由替身处理，测试不产生费用。仅修改文档无需安装运行依赖。

`requirements.txt` 列三个直接依赖；[constraints.txt](constraints.txt) 记录当前 **Windows / Python 3.11.5** 下全部 **43 个运行时间接依赖**的已安装版本，包括 Flask、AKShare、OpenAI SDK 的逐层依赖及共用包。清单依据包元数据和当前平台条件核对，不使用整个环境的 pip freeze，不记录无关包、可选 extras 或构建工具。约束文件只限制实际需要安装的包版本，详见 [pip 官方说明](https://pip.pypa.io/en/stable/user_guide/#constraints-files)。

这是一份已验证平台的版本快照，不是跨平台或带文件哈希的完整锁文件。colorama、mini-racer 保留 Windows 条件；Linux 专有依赖尚未验证和锁定，其他 Python/操作系统也尚未验证。新增直接依赖或调整版本后，应重新核对依赖链和约束，并运行项目测试。安装前可用 `python -m pip install --dry-run -r requirements.txt -c constraints.txt` 查看是否会调整已有包，存在冲突时先检查影响或使用独立环境，不批量升级。

启动本地开发服务：

```powershell
python run.py
```

打开 <http://127.0.0.1:5000/> 查看首页。在另一个终端检查健康接口：

```powershell
python -c "from urllib.request import urlopen; print(urlopen('http://127.0.0.1:5000/health').read().decode())"
```

返回 JSON `{"status":"ok"}`（空白格式可能不同）。它表示 Web 进程可响应，不检查业务数据库或外部服务。用 `Ctrl+C` 停止。端口被占用时可运行 `python run.py --port 5001`，并将浏览器和检查命令中的端口同步改成 5001。服务仅监听本机回环地址，默认关闭调试，不用于远程部署。

从其他工作目录运行时，传入 `run.py` 的实际路径即可。例如从项目根目录用 PowerShell 取得路径后，切换到上一级再启动：

```powershell

Set-Location ..
python (Join-Path $projectPath 'run.py')
```

停止后可用 `Set-Location $projectPath` 返回。路径来自代码文件位置，与终端工作目录无关。

## 网页使用

首次克隆或取得包含迁移的代码后，先执行 `python -m flask --app app:create_app init-db`；已有 T05 版本 3 的库会先备份再应用 004 归档迁移，不需重新填充 SP/CA。按后文配置本机密钥路径，然后 `python run.py` 打开 <http://127.0.0.1:5000/>。仅希望使用虚构演示时才显式执行 `seed-demo` 和 `md-refresh`。

- **财务档案**：编辑金额、风险偏好、目标和持仓后统一点击“保存财务档案”。删除子项会先确认，再从草稿移除，保存后才写库。空白表示未知，明确的零会保留。已确定的基础币种不可直接修改。版本冲突时保留输入，需手动重新读取并核对，不会自动重试；重新读取会在确认后丢弃未保存草稿。
- **对话记录**：新建/选择会话，发送问题并等待助手回答；角色和模型用量分开显示，刷新或重启后仍可查看。模型失败保留用户原文，原问题旁显示“重试”按钮，不写假助手回复。已保存问题确认后清空对应草稿；HTTP 状态不确定时先重新读取，保留未保存输入。同会话未完成问题需先处理，不能插入新问题；历史摘要中的“当时确认”不是当前 SP。
- **待确认变更**：查看修改内容、来源会话/原始用户消息、状态和基于的档案版本。同归档批次先逐条拒绝不想应用的项，再点击“合并确认剩余N项”，核对每项原文后一次更新档案。单条确认仍保留；拒绝不改 SP。查看和切换页签不会自动处理候选。本轮不提供候选编辑器。
- **市场数据**：按当前提供器列目录、只读已有缓存，手动刷新才调用该提供器。显示精确值、单位、真实/模拟标记、AKShare 与对应上游、数据日期、获取/过期时间、缓存和刷新状态。无缓存显示“暂无数据”，过期旧值和刷新错误都会保留；日期不补造时刻，指数点位无币种。模式切换见下文。

所有写入均调用后端服务；详细契约见 [HTTP 接口说明](docs/API.md)。当前结构版本为 4，本轮新增 `004_archive_workflow.sql`，001–003 保持原样。

### 对话归档与跨会话记忆（T07）

在“对话记录”完成一轮聊天后，点击“生成归档摘要”并确认模型费用。页面显示本次消息范围、进行中状态、成功的摘要版本及新建待确认项数量。展开“查看会话摘要”和 Overview；候选在“待确认变更”页查看原始用户消息、确认或拒绝。只有确认成功才修改 SP；拒绝不会改 SP，也不会因重复归档同一证据重新出现。

后续新会话读取当前确认 SP、最新 Overview 和本会话近期消息；Overview 是历史解释，不能把旧预算、假设或未确认意向当作当前值。T08 可按需查询更多历史摘要，但不浏览其他会话原文。普通发送不会触发归档。

归档按序号处理尚未归档的完整 user/assistant 轮次，T05 轮次必须已成功保存。兼容没有聊天请求记录的相邻旧 user/assistant 对；纯用户消息、system/tool 和失败轮次不会归档，可定位其后的完整连续段，但前置消息不包含在范围内，也不标为已归档。默认每次最多 20 条消息、正文合计 24000 字符（另有固定提示与 ID 元数据），不截断单轮；太长时留给下一段，单轮本身超限时提示调整配置，不假装已读。范围由服务端计算并明确显示，成功后的相同范围重复操作返回原结果。参数为 Config.ARCHIVE_MAX_MESSAGES（2–100）和 ARCHIVE_MAX_CHARS（2000–64000）。

归档使用同一 SDK、配置和密钥保护机制，最多输出 2048 tokens、超时 60 秒，不自动重试。失败保留原聊天、先前摘要及 Overview，提供原范围的明确重试；进程中断后 180 秒可重试，可能再次计费。一个会话只保留一个未完成归档，不同会话可并行；归档期间可继续正常聊天，新消息留待下一次。等待模型期间不持有写锁，摘要、Overview、候选及成功状态同事务保存。迟到旧尝试不能覆盖新结果。

模型摘要必须包含七类有界条目及本次消息 ID 引用，后端校验后才转为现有 CA 结构。Overview 在提交时重新读取最新来源；只有同会话、更高版本的成功归档分段合起来完整覆盖旧范围时，才移除被替代的来源。例如旧摘要#1–#4遇到新段#1–#2时仍保留，等#3–#4也成功归档后再替代，避免丢失未覆盖的理由。

Overview每类最多30项、来源最多100个，仍按会话轮流取条目并对完全相同文本去重。达到来源上限不再阻断归档：本次来源优先保留，其余按摘要创建时间倒序，时间相同再按会话ID、摘要版本、摘要ID倒序，保留前99个。本次摘要的条目也优先进入合并。退出Overview的来源仍在历史摘要及旧Overview中；没有删除原始消息。旧版本因 memory_limit 失败的范围可用原重试按钮继续，可能产生模型费用。

自动候选仅限基础收入、支出、现金、负债、储蓄/投资预算和风险偏好。模型结合本次对话和当前SP判断明确变更意图，不要求“改为”“设为”等固定句式；提示词要求假设、举例、转述、助手建议或意图/金额/币种不明确时省略候选。模型还负责理解倍率和金额口径：CNY明确时，“900，单位是万元”应输出基本单位字符串 `"9000000"`，不是 `"900"`。

后端只校验候选契约：操作/字段白名单、金额非负有限十进制字符串（基本单位，不带千分位/符号/倍率，最多两位有效小数）、独立currency字段及既有币种约束；未知用null、零用 `"0"`，不舍入或换汇。来源ID必须属于本次归档的已保存用户消息，evidence必须等于完整原文。单条无效候选被跳过，有效摘要和其他候选照常保存；整个响应或摘要无效才使归档失败。重复来源和无变化值仍会过滤。

来源校验只能证明“引用确实来自这条用户消息”，不能证明模型正确理解了意图、倍率或币种。即使输出结构合法，模型仍可能把假设误当要求、把万元转换错。候选卡片、单条与批次确认框同时显示拟写字段、新值、币种和原文，请用户逐项核对，不正确的先拒绝；确认前SP不变。目标/持仓仍手动维护。模型替身测试只验证契约和保存/确认流程，不等于真实语义能力验收。

同批次的合并确认仅应用页面核对过的全部剩余待确认项，拒绝项不生效。服务端检查批次归属、状态、相同SP基准版本和字段冲突，在一个事务内更新SP一次、确认全部候选；同字段相同目标值去重，不同目标值会提示先逐条拒绝冲突项。重复确认已完成的相同集合不重复应用。档案被表单或其他候选改动后仍报版本冲突，不自动换版本；先单条确认某项也可能使其余项冲突，因此多项优先合并确认。结构仍为v4，本次修复无需迁移或安装依赖。

人工验收建议使用下节的隔离副本：初始预算设为800，先发送“如果以后改成900”并归档，检查本次新建候选为0（seed-demo已有候选与本次无关）；再发送“把每月投资预算改为900，因为日常支出减少了”并归档，确认前预算仍800，确认后900。新建会话询问预算、理由和旧计划，刷新后检查历史仍在。用无效本机模型路径模拟归档失败，恢复配置后点击原范围重试。桌面和约390px宽度均检查按钮、状态、摘要、候选原文、无横向溢出，并查看浏览器控制台。本轮浏览器通道不可用，HTTP/服务测试不能代替这些视觉检查。

浏览器人工复查：在新的隔离副本中，连续发送两个明确财务安排后归档，核对候选与原文，先拒绝一项再合并余项。另建两个批次，第一批确认成功后确认仍基于旧版本的第二批，页面应只显示本次版本冲突、包含基于/当前版本，不残留上一轮成功提示。单条确认、批次确认及拒绝均应清理旧提示；取消确认不发送写入请求。桌面和约390px窄屏检查确认框、金额单位、原文换行及控制台。本机浏览器通道不可用；本轮使用模型替身和Node DOM/API替身测试提示及确认流程，不替代浏览器视觉验收，没有真实模型抽检。

### 隔离的人工网页检查

本轮自动浏览器通道不可用，未完成浏览器视觉、窄屏、键盘与控制台验收。已执行隔离库 HTTP 串联、全部 unittest 和前端 JavaScript 语法检查；这些不能替代浏览器验收。人工操作请先建立项目内独立副本，避免改变当前开发数据（以下在项目根目录的 PowerShell 逐行执行）：


打开 <http://127.0.0.1:5001/>，可依次检查：

1. 编辑金额、增加/编辑/删除目标和持仓，保存后重新载入；用两个标签页基于同一版本编辑，先保存其中一个，再保存另一个，确认出现冲突且保留输入。
2. 配置副本的本机密钥路径，新建两个会话并发送虚构问题，追问后刷新/重启，确认用户与助手消息均保留、归属正确。发送会产生费用。用无效配置模拟失败，应仅保留用户消息并显示明确重试入口；修复后重试不新增同一用户消息。连续点击、同请求 ID 重发不能重复成功回复。展开摘要/Overview，确认聊天未自动更新它们。
3. 在不同的新副本中分别确认和拒绝待确认候选，检查档案版本及预算；仅查看不能修改。处理后按钮应消失。

5. 将视口缩窄，检查自然堆叠与无横向溢出；用 Tab、方向键和 Esc 操作页签/确认框，检查可见焦点，并查看开发者工具控制台是否有异常。

用 `Ctrl+C` 停止副本服务。测试副本的数据位于该副本的 `runtime/`，不会写入原开发库；不要复制真实密钥或个人资料进行检查。

### 聊天上下文、失败与并发

网页发送最长 4000 字符的问题。后端先保存用户消息，再读取当前确认 SP、最新 Overview（可无）和当前会话最近最多 12 条 user/assistant 消息，最后追加本次问题一次。SP/Overview 以 user 数据消息中的 JSON 提供，不作为 system 指令；system 由后端固定维护，待确认意向与旧摘要不能代替当前 SP。默认初始内容上限 16000 字符，结构化上下文约 6000 字符，目标/持仓各最多 10 项，概览各类最多 3 项并可截短；超限先减少子项或旧消息，不截断基础金额、不丢掉当前问题。不做精确 token 计数。其他会话原文不混入，跨会话背景通过 Overview 和受限的摘要查询提供。

正常聊天默认输出最多 1024 tokens、超时 60 秒；连通检查仍为 64 tokens、30 秒，且不读取业务数据。聊天参数集中在 Config 的 CHAT_RECENT_MESSAGES、CHAT_CONTEXT_CHARS、CHAT_MAX_TOKENS、CHAT_TIMEOUT_SECONDS，可由 create_app 测试/应用配置覆盖；边界见代码。所有模型调用只在发送、显式归档、明确重试或显式检查时发生，可能计费；未提供用量时不估算。

请求 ID 绑定问题，成功后的重复请求直接返回已保存回复。失败不会写假助手消息；点击原问题的重试按钮会复用用户消息，但重新调用可能再次计费。模型已返回而保存失败时会明确说明。HTTP 结果未知请先读取会话，同一页面再次提交相同草稿沿用请求 ID。前端同一窗口一次发送；后端通过数据库约束保证同一会话只有一个未完成问题，不同会话可并行，旧的原文保存接口也不能插队。

若服务进程中断，running 状态不自动代表失败；工具版默认占用期延长为 510 秒，为模型和行情等待预留时间，到期只读界面显示 interrupted，可明确重试。期限为 max(180, (工具轮数+1)×模型超时+工具总数×75+30) 秒，注入整个替身模型的旧测试路径仍使用原期限。新尝试用不同 attempt_id，迟到旧回复不能覆盖新结果。没有自动网络重试、后台恢复或队列；尚无法确认外部是否已计费时请谨慎重试。等待模型/行情时不持有 SQLite 写锁，成功回复与请求成功状态原子保存。

### 聊天工具与 MVP 演示（T08）

沿用上文外部密钥配置和 `python run.py`，无需另建工具配置。模型可直接回答当前预算，也可通过 SDK Chat Completions 的 tools/tool_calls 选择以下工具；协议参考 [OpenAI 官方文档](https://developers.openai.com/api/docs/guides/function-calling) 和 [百炼 Function Calling](https://help.aliyun.com/zh/model-studio/qwen-function-calling)。普通文本、T07 JSON 归档和连通检查继续复用同一 SDK 模块。

- `search_history`：1–80 字关键词仅匹配摘要各类别数组内的正文条目，不匹配固定JSON字段名；字面、不区分英文大小写匹配，先筛正文再取最多5条，每个相同会话/覆盖范围只选最新摘要版本。可找到 Overview 未收录的历史，不是全文语义检索；返回有长度限制的摘录、会话 ID、摘要 ID/版本/覆盖序号。找不到就明确无匹配。历史计划不等于当前状态。
- `query_market`：仅当前目录完整资产 ID 和支持的指标；不明确时先询问。沿用 MD.query：有效缓存优先，过期或缺失才获取；聊天不提供强制刷新参数。默认 mock；真实模式仍按上文设置 MD_PROVIDER_ID 并重启。结果保留单位、币种、来源、数据时间、获取/过期时间、模拟标记及错误。fresh 只代表近期获取，股票/指数为日线，基金为正式净值，不是实时行情。可识别的上游 HTTP429 单独标记 rate_limit；未提供状态码的错误只报告获取失败，不猜原因。
- `calculate_savings`：固定月存入，不计收益、通胀、费用或汇率。差额=max(目标−已存,0)，月数=向上取整(差额/月存入)。已达标为 0 个月，差额>0且月存入为0时无法达成；未知输入提示缺项，币种不一致不换汇。金额复用两位 Decimal 文本。可读取确认目标的 target_amount 和 SP.savings_budget；SP 没有目标已存金额字段，不能用现金或 investment_budget 代替，须用户补充。模型理解情景、倍率和币种，工具只校验契约并计算；情景不写入 SP。

储蓄结果由后端固定说明具体缺项、币种冲突或零存入原因，区分“无法给出月数”和“已达标，0个月”。没有可用月数且没有其他可用结果时，保存后端说明作为最终回复；历史实际命中records或行情返回可展示data时（包括明确标注为过期的缓存），才保留其他回答和依据，独立显示“储蓄计算（后端结果）”。空历史、行情失败无数据及因上限跳过均不算可用结果，可另附固定无结果提示。补齐输入重算成功后，以最后一次结构合法的计算结果为准，已解决的缺项不再显示。后端不解析原话或按关键词过滤模型回复。

默认最多 2 轮工具、总共 4 次工具执行（含无效调用），最多 3 次模型请求；Config.CHAT_TOOL_ROUNDS 允许1–4，CHAT_TOOL_CALLS允许1–8，可由应用配置覆盖。达到预算后用 tool_choice=none 请求最终文本，若模型仍请求工具则本轮失败。每次参数最多4000字符、单项结果最多6000字符；含中间消息的序列化上下文最多 CHAT_CONTEXT_CHARS+32000（默认48000）字符，超出明确失败而非删掉当前问题。结果或参数无效、查询失败会送回结构化错误，并在最终回复附工具提示，防止遗漏失败状态。历史/行情结果另附后端生成的“工具依据”，准确列出来源ID，或数值、单位、日期、模拟标记和缓存状态，便于核对模型措辞。用量仅累加每轮都提供的同名 token 字段，不估算缺失轮次；多轮会增加等待和费用。工具没有 SP、摘要、候选的写权限，只有 MD 正常缓存更新会写行情表。

`app/config.py` 使用 `pathlib` 从代码位置定位根目录，统一约定：

| 路径 | 用途 |
| --- | --- |
| `runtime/data/` | 本地数据库 `app.sqlite3` |
| `runtime/logs/` | 需要时产生的日志 |
| `runtime/imports/` | 未来的实际导入数据 |
| `runtime/backups/` | 升级前的数据库备份 |
| `runtime/tests/` | 测试临时文件与临时数据库 |

目录按需创建；Web 启动不创建数据库，只有显式初始化命令创建业务库；测试只写独立测试目录。源码与持久化引用不得绑定用户名、盘符或本机绝对路径。

`library/` 是各成员的本地背景资料，不修改或提交；`runtime/` 是各成员自己的运行数据；公开源码、测试、文档及依赖清单由 Git 管理。新克隆的仓库不含背景资料、运行数据或真实配置。

普通 Web 启动不读取模型配置，也不自动加载 `.env`。发送聊天、显式归档或连通检查时优先使用 PFC_LLM_CONFIG_FILE，未设置时读取项目根目录 config.local.json 中的路径，再读取项目外私密 JSON；真实密钥不进入项目。真实 `.env`、`config.local.*`、数据库及附属文件已忽略。无密钥的 `.env.example`、迁移 SQL、数据脚本和合成测试样例允许纳入 Git。

## 整体迁移与协作

停止服务与其他数据库写入，将整个项目文件夹复制到新位置，在新环境检查 Python 并按需安装 `requirements.txt`，再执行启动和测试命令，无需修改路径。若要保留 Git 历史，复制时包含 `.git`；携带本地数据时包含 `runtime/`。数据库没有指向原目录的绝对路径，可在副本继续使用；若采用新克隆，则按需初始化新库，不会获得原机器的本地数据。私有资料和密钥单独安全传递，不通过公开仓库同步；Python 环境不随文件夹迁移，使用新机器自己的解释器。
